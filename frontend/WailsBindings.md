# Wails Bindings Policy

## Generated Code Location

Wails TypeScript/JavaScript bindings are auto-generated by the Wails CLI and placed in:
```
frontend/src/wailsjs/
```

## Generation

The bindings are automatically generated when you run:
- `wails dev` - Development mode (generates bindings on startup)
- `wails build` - Production build (generates bindings before building)

The output directory is configured in `wails.json`:
```json
"wailsjsdir": "./frontend/src/wailsjs"
```

## Git Policy

**DO NOT COMMIT** `frontend/src/wailsjs/` to version control.

This directory is:
- Auto-generated from Go code annotations
- Platform-specific in some cases
- Regenerated on every build
- Listed in `.gitignore`

## Usage in Frontend

The frontend code should check for Wails runtime availability before using bindings:

```typescript
import { isWailsRuntime } from './api/client';

if (isWailsRuntime()) {
  // Use real Wails bindings
  await window.go.main.App.SomeMethod();
} else {
  // Fallback for browser dev/testing
  // Use mock implementations
}
```

## Regenerating Bindings

If bindings are missing or out of date:
1. Run `wails dev` (development mode)
2. Or run `wails build` (production build)
3. The bindings will be automatically generated

## TypeScript Configuration

The `tsconfig.json` includes a path alias for the bindings:
```json
"@/wailsjs/*": ["./src/wailsjs/*"]
```

This allows importing like:
```typescript
import { App } from '@/wailsjs/go/main/App';
```

However, the current implementation uses runtime detection (`window.go.main.App`) which is more flexible for browser fallbacks.
